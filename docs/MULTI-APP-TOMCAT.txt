SEVERAL WAR APPLICATIONS ON ONE TOMCAT
======================================

Yes. One Tomcat can run GeoServer, GIS Warplan, and other WARs at the same
time. Each WAR is its own application. They share the JVM and the HTTP port.
They do not share URLs, classloaders, databases, or configuration files.

This note is only about that. For building GIS Warplan and placing its UI,
read DEPLOYMENT.txt in this folder.


1. How Tomcat treats each WAR
-----------------------------

Every file or folder under TOMCAT/webapps is one application.

  Name on disk                         Browser address
  -----------------------------------  ------------------------------------
  webapps/ROOT/  or  ROOT.war          http://HOST:PORT/
  webapps/gis-warplan.war              http://HOST:PORT/gis-warplan/
  webapps/geoserver.war                http://HOST:PORT/geoserver/

The part after the host and port is the context path. It is the WAR file
name without .war. ROOT is the special name for the empty path /.

Rules that must stay true:

  - Two applications must never use the same context path.
  - Do not put two products into one WAR.
  - Do not create a folder named gis-warplan and also drop gis-warplan.war
    for a different product. Tomcat treats them as one application.
  - Replacing one WAR does not replace another WAR.


2. What they share, and what they keep separate
-----------------------------------------------

Shared by every application on that Tomcat

  - One JVM (one heap, one JAVA_HOME)
  - One HTTP Connector port (for example 8080)
  - One shutdown port (default 8005)
  - Tomcat's own lib/ and conf/server.xml

Separate for each application

  - Context path and URL
  - Its own WEB-INF classes and libraries
  - Its own database connections and credentials
  - Its own data folders (icons, logs, GeoServer data directory)
  - Its own sessions and security

So GeoServer and GIS Warplan can both be "UP" on the same host and port.
Opening /geoserver/... does not touch /gis-warplan/..., and the reverse is
also true.


3. Tomcat version matrix (read this first)
------------------------------------------

Official GeoServer packaging (from GeoServer WAR install docs):

  GeoServer line   Servlet API   Compatible Tomcat   Notes
  ---------------  ------------  ------------------  -------------------------
  GeoServer 3.x    Jakarta 6.1   Tomcat 11.0.x       Current stable. Use this.
  (none)           Jakarta 6.0   Tomcat 10.1.x       GeoServer does not support
                                                     Tomcat 10.1.
  GeoServer 2.x    Java EE 4     Tomcat 9.x          Maintenance line only.

GIS Warplan (Spring Boot 3 / Jakarta) runs on Tomcat 10.1 and also on
Tomcat 11.0.

Therefore, to put GeoServer and GIS Warplan in the SAME Tomcat process:

  Use Tomcat 11.0.x
  Use GeoServer 3.x WAR (latest stable at the time of writing: 3.0.2)
  Use the current gis-warplan.war

Do not put GeoServer 2.x into Tomcat 10.1 or 11 (wrong servlet API).
Do not put GeoServer 3.x into Tomcat 10.1 (officially unsupported).

If you must keep a Tomcat 9 GeoServer, run it as a second Tomcat (or keep
the Windows/Jetty GeoServer service) on another port, and keep Warplan on
Tomcat 10.1 or 11. That is still one server machine; it is not one Tomcat.


4. Prerequisites for this pattern
---------------------------------

  - JDK 17 or 21. JAVA_HOME set.

  - Apache Tomcat 11.0.x when GeoServer 3 and Warplan share one Tomcat.
    Example used in this project: apache-tomcat-11.0.29.

  - GeoServer 3.x Web Archive. Download geoserver-VERSION-war.zip from
    https://geoserver.org/download/ (Stable). Unpack it; inside is
    geoserver.war. Latest stable at the time of writing: 3.0.2
    (geoserver-3.0.2-war.zip).

  - Enough RAM for both applications in one JVM. Example:

      set "CATALINA_OPTS=%CATALINA_OPTS% -Xms512m -Xmx2048m"

  - Free HTTP port for that Tomcat. If a standalone GeoServer Windows
    service already owns 8080, stop that service before starting Tomcat
    on 8080, or give Tomcat another Connector port.

  - Separate data directories. Warplan icons/attachments/logs are not
    GeoServer's data directory. Point GEOSERVER_DATA_DIR at a folder
    outside webapps.


5. Layout on one Tomcat (example)
---------------------------------

Tomcat 11 listens on port 8080.

  C:\apache-tomcat-11.0.29\
    bin\setenv.bat
    conf\server.xml              Connector port="8080"
    webapps\
      ROOT\                      GIS Warplan UI (static dist)
      gis-warplan.war            GIS Warplan API
      geoserver.war              GeoServer 3.0.2

Addresses:

  GIS Warplan UI:     http://HOST:8080/
  GIS Warplan API:    http://HOST:8080/gis-warplan/api/v1
  GIS Warplan health: http://HOST:8080/gis-warplan/actuator/health
  GeoServer:          http://HOST:8080/geoserver/

If GIS Warplan has no UI on this Tomcat, leave ROOT empty or leave the
default Tomcat welcome page. The API still runs at /gis-warplan/.

GeoServer's own web UI is already inside geoserver.war. You do not copy
a separate frontend for GeoServer.


6. Configure Tomcat once
------------------------

6.1 HTTP port

  Edit conf/server.xml, Connector port. One number for every WAR on this
  Tomcat. Example:

    <Connector port="8080" protocol="HTTP/1.1"
               connectionTimeout="20000"
               redirectPort="8443"
               maxParameterCount="1000"
               />

6.2 setenv for both products

  Create TOMCAT/bin/setenv.bat (Windows) or setenv.sh (Linux).

  Windows example used when both products share Tomcat 11:

    set "SPRING_PROFILES_ACTIVE=prod"
    set "DB_URL=jdbc:postgresql://localhost:5432/gis_warplan"
    set "DB_USER=postgres"
    set "DB_PASSWORD=the-real-database-password"
    set "WARPLAN_JWT_SECRET=a-long-random-string"
    set "WARPLAN_ICONS_ROOT=C:/coraltelecom/gis-warplan/images/icon"
    set "WARPLAN_ATTACHMENTS_ROOT=C:/coraltelecom/gis-warplan/images/scenario-attachments"
    set "GEOSERVER_DATA_DIR=C:/ProgramData/GeoServer"
    set "JAVA_OPTS=%JAVA_OPTS% -Dlogging.config=C:/coraltelecom/gis-warplan/config/gis-warplan.xml -DGEOSERVER_DATA_DIR=%GEOSERVER_DATA_DIR%"
    set "CATALINA_OPTS=%CATALINA_OPTS% -Xms512m -Xmx2048m"

  Warplan variables are ignored by GeoServer. GEOSERVER_DATA_DIR is ignored
  by Warplan. Do not reuse the same variable name for different meanings.

  If you previously ran the GeoServer Windows installer, its data often
  lives at C:\ProgramData\GeoServer. Reuse that path so layers survive.
  Otherwise create a new empty folder, for example
  C:\coraltelecom\geoserver\data_dir, and point GEOSERVER_DATA_DIR there.

6.3 Stop any other GeoServer on the same port

  Windows service example (needs an Administrator prompt):

    net stop GeoServer

  Or Services.msc -> GeoServer -> Stop.
  Leave that service set to Manual so it does not fight Tomcat on reboot.

6.4 Start Tomcat once

  set CATALINA_HOME=C:\apache-tomcat-11.0.29
  set CATALINA_BASE=C:\apache-tomcat-11.0.29
  C:\apache-tomcat-11.0.29\bin\startup.bat

  One start loads every WAR under webapps. GeoServer's first deploy unpacks
  a large WAR and can take several minutes.


7. Deploy each WAR without disturbing the others
------------------------------------------------

GIS Warplan API

  Copy target\gis-warplan.war to webapps\gis-warplan.war
  Leave geoserver.war and ROOT alone.

GeoServer

  Download geoserver-VERSION-war.zip, unpack, copy geoserver.war to
  webapps\geoserver.war
  Leave gis-warplan.war and ROOT alone.

GIS Warplan UI (optional)

  Copy the frontend dist into webapps\ROOT
  Edit ROOT\config.js so apiBase is /gis-warplan/api/v1
  Leave the two WAR files alone.

Never name the UI folder the same as another WAR's context. Never put the
Warplan UI inside webapps\geoserver.


8. Same machine, two Tomcats instead of one
-------------------------------------------

Use this when products disagree on Tomcat major version, or when you want
separate heaps and restarts.

  Tomcat A (9.x):   GeoServer 2.x only. Port 8080. Shutdown 8005.
  Tomcat B (10.1+): GIS Warplan only. Port 8180. Shutdown 8006.

Or keep the GeoServer Windows/Jetty service on 8080 and Warplan on Tomcat
10.1/11 on another port. That is what this machine used before both WARs
were moved onto Tomcat 11.

Each Tomcat has its own CATALINA_HOME or CATALINA_BASE, its own setenv,
and its own webapps.


9. Check that both are independent
----------------------------------

  http://HOST:PORT/gis-warplan/actuator/health   -> {"status":"UP"}
  http://HOST:PORT/geoserver/                    -> GeoServer welcome / login
  http://HOST:PORT/                              -> Warplan UI (if ROOT has dist)

  Redeploying one WAR must not remove the other.
  Warplan logs go to the folder in LOG_BASE (DEPLOYMENT.txt).
  GeoServer logs go to its data_dir logs or Tomcat logs, not into Warplan's
  app.log.


10. Typical problems
--------------------

Port already in use
  A standalone GeoServer service still owns 8080. Stop it, or change
  Tomcat's Connector port.

GeoServer fails on Tomcat 10.1
  Expected. Use Tomcat 11 with GeoServer 3, or keep GeoServer on Tomcat 9 /
  its own service.

One WAR disappears when the other is updated
  The two products were given the same context path. Rename one WAR.

Warplan login page is GeoServer, or GeoServer URL shows Warplan JSON
  Wrong context path. Use /geoserver for GeoServer and /gis-warplan for
  the Warplan API. Warplan UI is / only when dist was copied to ROOT.

Out of memory
  Raise CATALINA_OPTS -Xmx. Two large WARs need more heap than one.

GeoServer data wiped after redeploy
  GEOSERVER_DATA_DIR was not set, so data lived inside the exploded WAR.
  Set an absolute GEOSERVER_DATA_DIR outside webapps.


11. Short answer
----------------

Yes. On Tomcat 11, put geoserver.war (GeoServer 3.x) and gis-warplan.war
side by side in webapps, keep different names, keep different data
folders, share one HTTP port, and start Tomcat once. Each product then
opens on its own path and runs without sharing code or configuration
with the other.

Latest combination documented here:

  Tomcat          11.0.29
  GeoServer WAR   3.0.2   (from geoserver-3.0.2-war.zip)
  GIS Warplan     current gis-warplan.war + optional UI in ROOT
